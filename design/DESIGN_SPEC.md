# Design specification / Manga Nikki — Monochrome

## 目的と判断基準

この UI はストア/LPのような宣伝画面ではなく、日々使うスマホ用日記アプリです。アプリ紹介文・オンボーディング・英語装飾ラベルを画面に追加しません。審査デモで、何も説明しなくても「日記を書く→漫画を見る→カレンダーで振り返る」がわかるようにします。

## 配色

`design_tokens.json` が正本です。

- ベース背景：`#FFFFFF`
- カード：`#F6F6F6`; 補助カード：`#EFEFEF`
- 選択中タブ：`#EBEBEB`
- 主要テキスト：`#252525`; 副次テキスト：`#858585`
- 区切り線：`#EBEBEB`; 枠線：`#E4E4E4`
- 強い主CTA：`#222222`、白文字
- Google Fontsの Noto Sans JP または手元で画面に一致する日本語ゴシック。フォントの字面差を確認。

## 視覚グリッド（モックの基準）

- 元デザイン：390×844（うちトップ0〜55px、ボトム825〜843pxはiOS風の**装飾**）
- ブラウザの見た目比較用：390×769（元画像の y=56〜824 を切り出し）
- 水平余白：主に24px。コンテンツ幅342px。
- 主CTA（元画像）：x=24 y=680 w=342 h=54, corner-radius 14〜15px
- 下部ナビ（元画像）：x=16 y=748 w=358 h=76, corner-radius 26px
- 主CTA下端→ナビ上端：14px。ページ表示領域・safe-areaに合わせてCSS固定配置する。絶対座標をそのまま全端末にコピーしない。
- タップ可能領域：原則44px以上。色だけで状態を表さない。

## 画面構造：4ルート＋状態

- `/` : 今日が空/記録ありで上部カードが切り替わる。最近の記録を下に置く。
- `/new` : 日付・大きな入力欄を中心にし、主CTA「4コマにする」を下端に固定。**下書き保存は上部ヘッダー右上**。未保存離脱の確認あり。
- `/library` : 月間カレンダーを初期表示。記録した日に黒い点。選択日の記録を下に表示。同日複数件可。右上で一覧に切り替え。
- `/entries/:id` : 画面状態に応じて完成した4コマ/下書き/生成中/失敗/確認中を表示。「…」の中に編集・削除。**削除は確認ダイアログ**。元の日記本文は折りたたみ/展開可。

### 生成状態の詳細

- `queued` → 画面09。待機中であることを表示。勝手な推測進捗や残り秒数は出さない。
- `running, stage=script` → 画面10。構成を考える。
- `running, stage=images` → 画面11。絵を描く。
- `running, stage=saving` → 画面12。保存する。
- `succeeded` → 画面07（4画像）、画面25（1画像）。APIの `ComicDocument.visual.kind` に応じて切替。
- `unknown` → 画面13。勝手に再生成しない。
- `failed` → 画面14。日記本文を保持し、可能な操作のみ表示。
- `cancelled` → 画面15。
- quota / offline / session unavailable → 画面16/17/23。実際の状態に応じて表示。

## 主CTAと補助操作の情報設計

**主CTAは画面内に複数置かない。** デフォルトでナビの直上。日記/下書き画面では生成を主操作として優先する。

- 「4コマにする」 → 下部ナビ直上。押下時に二重生成させない。
- 「下書き保存」 → 日記入力/編集の**右上**。
- 「日記を編集」 → 詳細画面の「…」内。下書きの場合は本文カード付近に編集導線を設けてもよい。
- 「日記を削除」 → 詳細画面の「…」内、タップ後ダイアログ。
- 「元の日記を読む」 → 漫画の直後の折りたたみ行（鑑賞の邪魔をしない）
- 生成中「記録を見る」 → ナビ直上。ただし生成処理は画面遷移と独立。
- 削除ダイアログ/未保存確認では背景操作不可、ナビ操作不可。

## ボトムナビの幾何

- 左：家のアイコン、中央：**プラス**、右：カレンダー。
- 非選択タブ：アイコンのみ。
- 選択タブ：アイコンの**下**に `ホーム` / `書く` / `記録` を表示。
- 選択背景は薄灰色。親ナビ全体が rounded-rect。**選択セグメントを長方形で描き、親ナビの外周の角丸で clip**。左選択なら左外角のみ丸く、右選択なら右外角のみ丸く、内側は直線。中央は両側直線。
- 3等分の押下領域は常に同幅。ラベル表示でタブ位置がズレない。
- aria-label を必ず設定。`＋` は新規作成アクションとする。

## アセット

`assets/cat_sleeping.svg` と `assets/comic_*.svg` は元のモックから抽出した独立のベクター素材。これらはアセットとして利用してよい。ただし `/reference/svgs/*` の画面全体を `<img>` として実装してはいけない。

漫画サムネイルは本物の生成画像があるときはそちらを表示。架空サンプルをデータとして明確に区別する。

## 実装で守るべきこと

1. レイアウトはレスポンシブ。固定 390px 幅だけを前提にしない。320px / 390px / 430px / PC中央カラムを検証。
2. スマホキーボードが開いたとき、入力・CTA・ナビが重ならないようにする。必要に応じて入力中はナビ非表示、CTAは適切にスクロール可能にする。
3. iOS safe-area を `env(safe-area-inset-bottom)` / `top` で考慮し、PWA standalone と Safari の両方を確認。
4. ステータスバーの `9:41` やホームインジケータを、実Webアプリの DOM に入れない。
5. 過剰なラベル・英語装飾・チュートリアル・宣伝文を追加しない。
6. 30日で消えるという既存の保存ルールは変えない。UIのメイン領域に期限バッジを増やさない（必要な契約/同意/法的文面を破棄することとは別）。
7. 画面画像と構造化仕様が矛盾する場合、画像の装飾的矛盾（重複nav、モーダル下に背景が残るなど）は修正し、意図されたUXを優先。
