# MVP仕様v1（SPEC）

> 2026-10-27時点の設計仕様です。すでに実装済みの機能一覧ではありません。

## 1. 目的と対象範囲

「文章の日記を後からまとめて読み返すのが面倒」という課題を、「日記を書く → AIで4コマ漫画を生成 → 自動保存 → 振り返り」という体験で解決します。

- 基本方針：日本語・文章入力・4コマ固定。スマートフォン中心（PCでも利用可能）のPWAとして提供します。ホーム画面へのインストールは必須にしません。

### 優先度とスコープ

| 区分 | 内容 |
|---|---|
| P0（最優先） | 日記入力・下書き保存・4コマ生成・自動保存・一覧/詳細表示・本人の削除・状態/エラー表示 |
| P1候補（余力があれば） | PNG画像出力・セリフ修正・音声読み上げ・漫画本風閲覧・恒久アカウント |
| 対象外（作らない） | SNS機能・動画/ゲーム・YouTube連携・写真入力・課金・画風選択・本人写真のアバター化 |

※ P1機能はP0がすべて完成した後に選択します。未完成の機能を本番デモへ混ぜません。

### 公開の前提

匿名認証・所有者検証・非公開画像・回数/予算制限・緊急停止・重複防止・スマホ/PWA検証を満たしてから公開します。機能の優先度とは別の必須条件で、詳細は[OPERATIONS](OPERATIONS.md)に従います。

## 2. 画面構成と操作ルール

### ルート一覧

| ルート | 役割と必要な表示・操作 |
|---|---|
| `/` | 今日の記録と最近の記録を表示する。sampleを表示する場合は架空サンプルと明示する。入力画面・記録一覧への入口を設ける。閲覧するだけでは匿名ユーザー登録を行わない |
| `/new` | 日付と日記本文の入力、「下書き保存」「漫画にする」操作。記録の見出しは本文から作り、入力中に見出しプレビューを常時表示しない。まず日記を保存してから生成ジョブを作成し、エラー時でも入力した本文を失わないようにする |
| `/entries/:id` | 最新の生成状態・最後に成功して保存済みの漫画・元の日記本文・日付・記録の見出しを表示し、削除操作を用意する。再生成中や失敗後も保存済み漫画を保ち、新しい成功・保存完了時に切り替える。詳細画面では戻る操作と記録の編集・保存・その他の操作メニューを維持する。再訪時は既存の生成ジョブを取得して表示する |
| `/library` | コンテンツ上部中央のピル型カレンダー/リストタブで表示を切り替える。右側の再読み込み操作で記録とcursorを先頭から取得し直し、選択中のタブ・月・日を保ちながらページ位置を1へ戻す。6週カレンダーでは選択日の記録を2件ずつ、リストでは3件ずつ表示する。内部APIからは日付の新しい順に20件ずつcursorで取得する。表示状態はURLに保持し、詳細から戻ったときに復元する。各記録の見出しは日記本文から作り、下書き・生成中・失敗した記録も表示する。画像は遅延読み込み（lazy load）する |

共通のアプリ名ヘッダーは表示しません。各画面には支援技術から識別できるページ見出しを設けます。

### 入力・保存・編集の体験

- 本文は前後の空白を除いて1〜1,000文字、日付は当日以前。同じ日付に複数記録でき、未生成の下書きは最大20件です。
- 開いたままJSTの日付が変わったときは、今日の表示・カレンダーの今日/未来判定・日付入力の上限を更新します。入力中の本文と選択済みの日付は保持します。
- 2026-11-07に承認された生成運用は累積80USD・全体の固定回数上限なし・通常ユーザー3回/JST日です。運用者のデバッグownerは日次回数の例外としますが、初回実行とデバッグも累積予算へ含めます。同時実行1ジョブ・認証・CAPTCHA・`unknown`の予約保持・二重課金防止は例外ownerにも適用します。DB migrationだけでは生成や例外設定を有効化せず、承認値は別の運用手順で設定します。
- 公開CRUDでは、新しい日記作成はownerあたりJST日次50件・全体JST日次1,000件、物理回収前の行はownerあたり100件・全体5,000件までです。削除済み・期限切れの行も物理回収までは保持件数に含まれ、削除操作自体は制限しません。
- 利用者が説明の近くにある保存・生成ボタンを明示的に押した場合だけ匿名認証を始めます。閲覧・入力だけでは登録やCAPTCHAを開始せず、生成時に日記本文を外部AIへ送信する条件を事前に示します。
- 生成中は本文を編集できません。後で本文を編集した場合、古い漫画には編集前の内容から作られたことを表示します。
- 削除・期限切れの記録はすぐに非表示にします。永久保存は約束しません。

日付・編集競合・セッションの詳細は[APIの保存・編集ルール](API.md#entry-lifecycle)、物理削除と障害時の対応は[OPERATIONS](OPERATIONS.md)を参照してください。

## 3. 漫画の品質基準と画面の状態表示

### AI生成の品質ルール（事実への忠実さ）

- 日記の事実・出来事の順序・登場人物の識別を最優先します。
- 1つの出来事を4つの場面（4コマ）に分割して表現して構いません。
- 事実の捏造を禁止：日記に書かれていない重大な出来事・病気・事故・人間関係・発言・曜日・無理なオチを事実として勝手に追加しません。
- 主人公はシンプルな架空キャラクターとし、日をまたいだ外見の完全な固定までは保証しません。

### 表示形式とアクセシビリティ

- 漫画は「1枚画像方式（page）」または「4枚画像方式（panels）」の共通データ契約で表示し、画像とあわせて脚本テキスト（場面説明・キャプション・セリフ）も提供します。
- スマートフォンでは縦1列表示を基本とし、以下の使いやすさを確保します。
  - 画像の拡大表示
  - キーボード操作への対応・フォーカス表示・適切な`label`設定
  - 十分なタップ領域の確保
  - 色だけに頼らない状態表示（テキストやアイコンの併用）

### 画面の状態ごとの表示・動作

| 状態 | 画面の表示・動作 |
|---|---|
| 空の履歴 | 新規作成ボタンと使い方の簡単な説明を表示 |
| 認証中 / 生成中 | 入力内容を保持したまま、「待機 → 構成（脚本） → 描画（画像） → 保存」の進行段階を表示。根拠のない残り秒数は表示しない |
| 完了 | 元の日記本文・生成された4コマ漫画・保存完了の状態を表示 |
| 生成 / 保存失敗 | 保存済みと偽らず、再操作の方法と生成枠・費用の扱いを案内する |
| 結果確認中 | 再生成を促さず、確認中であることを案内。内部状態は[用語集](../README.md#glossary)を参照 |
| 上限到達 / 停止 / オフライン | 使えない理由を明示し、閲覧可能な架空サンプルや既存履歴を案内する |

## 4. MVPの完成条件

- 「日記入力 → 4コマ生成 → 保存 → 画面移動やリロード後の再取得」が一通り動き、作成した本人だけに表示されること。
- ボタン連打・通信再送・画面を閉じた後の再訪によって生成ジョブや課金が二重に増えず、最後の1枠に対する同時リクエストでも上限を超えないこと。
- 生成失敗・認証切れ・予算上限による停止が起きても入力した日記本文を失わず、削除済みや期限切れのデータが復活しないこと。
- 架空の日記を用いた品質評価で事実を捏造せず、デモ時に「架空サンプル」「事前録画」「その場での実生成」を明確に区別できること。
- Android ChromeおよびiPhone SafariのHTTPS環境で画面表示とPWA更新を確認し、日記の入力中に画面が自動リロードされないこと。
- 実際の生成画像でWorkersのCPU・メモリ・遅延・ストレージ容量を計測し、[OPERATIONS.mdの公開前チェック](OPERATIONS.md)をすべて通過すること。
