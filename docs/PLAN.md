# 開発計画（PLAN）

まずは「日記入力 → モック漫画表示 → 保存・再取得」を一通りつなぎ、その後に認証・実DB保存・実AIを段階的に組み込みます。
変更は小さなPRに分け、完了した段階から順次`main`へ統合していきます（初期基盤は実装済みで、後続段階は未実装です）。

---

## 1. 開発を進める順序

| 段階 | 作るもの | 完了の目安（ゴール） |
|---|---|---|
| 1. 初期基盤 | React / Hono・共有型・モックAPI・標準コマンド・CI | 秘密情報なしで起動し、「入力 → 固定4コマ表示 → 履歴確認」と標準検査がすべて通る |
| 2. 保存と認証 | 匿名Auth・日記CRUD・private画像保存・RLS / RPC | リロード後も本人の記録だけを取得でき、他人からのアクセスを拒否できる |
| 3. AIの評価・接続 | 脚本/画像adapter・出力検証・モデルと最大費用の評価 | 架空日記で品質・処理時間・費用・データ保持条件を確認する |
| 4. 生成の統合 | 原子的な枠予約・Queue・重複防止・障害復旧 | 「入力 → 実生成 → 保存 → 再訪」が通り、通信再送や中断で二重生成しない |
| 5. 公開準備 | スマホ実機/PWA確認・削除/期限処理・予算停止・デモ準備 | [公開前チェック（OPERATIONS.md）](OPERATIONS.md)を通し、少数の実生成で計測する |

### 進め方のポイント

- 参照するドキュメント
  - 初期基盤の範囲と確認コマンド：[CONTRIBUTING.md](../CONTRIBUTING.md)
  - 画面・サーバー・AIをつなぐ共通契約：[API.md](API.md)
- 並行作業について
  - 「段階2（保存と認証の実装）」と「段階3（AIモデルの評価）」は、段階1で作る共有型（`ComicDocument`等）に合わせて並行して進められます。
- 費用と公開のガードレール
  - AIモデルの実験も、必ず予算承認後に行います。
  - 外部からアクセスできる公開生成は、認証・予算制限・Queueがすべて揃うまで停止（無効化）しておきます。

## 2. 直近でチームで決めること

1. AIモデル・解像度・画像形式（1枚方式`page` / 4枚方式`panels`）
   - 利用するモデルID、生成品質・所要時間・費用、リトライ挙動、入力データの学習利用や保持条件を、実測結果とともに記録して決定します。
2. 費用負担と承認予算
   - 誰がいくらまで負担するかを明確にします。未決定の間は予算上限を`0`とし、実AIの生成は停止します。
3. Node.jsと依存パッケージの正確なバージョン
   - pnpmは手元に合わせて`12.11.2`を採用済みです。Node.jsも`24.22.1`をmiseの設定・lockfileへ固定済みです。package.jsonの`packageManager`は`pnpm@12.11.2`に揃えます。

### ハッカソン発表のルールと準備

- 発表時間・参加条件：全員参加、3分厳守（運営都合により2分へ変更される可能性あり）。
- 発表に盛り込む内容：
  - 開発のきっかけ（課題）
  - こだわった実装ポイント
  - 今後の展望
  - 実際の画面・動作デモ
- デモと録画の注意点：
  - 当日の通信トラブルや制限に備え、架空日記を使った操作録画と公開サンプルも用意します。
  - 発表や画面上では、「固定サンプル」「事前生成（録画）」「その場での実生成」を混同しないよう明示します。
  - ※ 大会期限・発表条件の根拠は、提供された公式しおりp.3〜4・p.11の記録に基づきます。

### スケジュールが遅れた場合の優先順位

- 開発が遅れた場合は、P1機能や見た目の装飾から削ります。
- 「認証・非公開保存・予算制限・重複実行防止」は削りません。もし公開条件（安全対策）を満たせない場合は、無理に実APIを公開せず、サンプル画面と録画動画で発表・紹介します。
