## 1. 開発を進める順序

| 段階 | 作るもの | 完了の目安（ゴール） | 最新branchの状態 |
|---|---|---|---|
| 1. 初期基盤 | React / Hono・共有型・モックAPI・標準コマンド・CI | 秘密情報なしで起動し、「入力 → 固定4コマ表示 → 履歴確認」と標準検査がすべて通る | 実装済み |
| 2. 保存と認証 | 匿名Auth・日記CRUD・private画像保存・RLS / RPC | リロード後も本人の記録だけを取得でき、他人からのアクセスを拒否できる | 匿名Auth・日記CRUD・編集・RLS / RPCは実装済み。共有DBへのmigration適用は未実施で、生成画像のprivate Storage保存と署名URLは未接続 |
| 3. AIの評価・接続 | 脚本/画像adapter・出力検証・モデルと最大費用の評価 | 架空日記で品質・処理時間・費用・データ保持条件を確認する | 実AI用の脚本/画像adapter、画像検証・保存接続、モデル評価とCmax承認は未完了 |
| 4. 生成の統合 | 原子的な枠予約・Queue・重複防止・障害復旧 | 「入力 → 実生成 → 保存 → 再訪」が通り、通信再送や中断で二重生成しない | 原子的な枠予約・claim / attempt / lease / unknown・固定mock Queue経路は実装済み。実AI・画像保存と実Cloudflare Queue接続は未完了 |
| 5. 公開準備 | スマホ実機/PWA確認・削除/期限処理・予算停止・デモ準備 | [公開前チェック（OPERATIONS.md）](OPERATIONS.md)を通し、少数の実生成で計測する | PWA・期限削除・環境別sample build・公開設定guardは実装済み。実スマホHTTPS・実Turnstile・実Cloudflare Queue / Cron・画像性能・Cmax承認・公開デモ準備は未完了 |

`Comic.tsx`の画像拡大と`loading="lazy"`も未実装です。残タスクはこの表と[公開前チェック](OPERATIONS.md)に記載した範囲です。

### 進め方のポイント

- 参照するドキュメント
  - 初期基盤の範囲と確認コマンド：[CONTRIBUTING.md](../CONTRIBUTING.md)

  - 「段階2（保存と認証の実装）」と「段階3（AIモデルの評価）」は、段階1で作る共有型（`ComicDocument`等）に合わせて並行して進められます。
  - タスクと完了条件：[保存・認証 #3](https://github.com/tossyhal/manga-nikki/issues/3)と[AI評価 #4](https://github.com/tossyhal/manga-nikki/issues/4)を並行し、両方の完了後に[生成統合 #5](https://github.com/tossyhal/manga-nikki/issues/5)、その後に[公開準備 #6](https://github.com/tossyhal/manga-nikki/issues/6)へ進みます。担当・期限は各Issueで合意して設定します。
- 費用と公開のガードレール
  - AIモデルの実験も、必ず予算承認後に行います。
  - 外部からアクセスできる公開生成は、認証・予算制限・Queueがすべて揃うまで停止（無効化）しておきます。

## 2. 直近でチームで決めること

1. AIモデル・解像度・画像形式（1枚方式`page` / 4枚方式`panels`）
   - 利用するモデルID、生成品質・所要時間・費用、リトライ挙動、入力データの学習利用や保持条件を、実測結果とともに記録して決定します。
2. 費用負担と承認予算
   - 誰がいくらまで負担するかを明確にします。未決定の間は予算上限を`0`とし、実AIの生成は停止します。
3. 開発ツールの固定版（決定済み）
   - pnpmは手元に合わせて`12.11.2`を採用済みです。Node.jsも`24.22.1`をmiseの設定・lockfileへ固定済みです。package.jsonの`packageManager`は`pnpm@12.11.2`に揃えます。

### ハッカソン発表のルールと準備

- 発表時間・参加条件：全員参加、3分厳守（運営都合により2分へ変更される可能性あり）。
- 発表に盛り込む内容：
  - 開発のきっかけ（課題）
  - こだわった実装ポイント
  - 今後の展望
  - 実際の画面・動作デモ
- デモと録画の注意点：
  - 当日の通信トラブルや制限に備え、架空日記を使った操作録画と公開サンプルも用意します。
  - 発表や画面上では、「固定サンプル」「事前生成（録画）」「その場での実生成」を混同しないよう明示します。
  - ※ 大会期限・発表条件の根拠は、提供された公式しおりp.3〜4・p.11の記録に基づきます。

### 大会の評価軸

提供された【技育CAMP2026】ハッカソンVol.6の公式しおりp.5の記録では、審査は「企画・アイデア」「影響範囲・完成度」「技術・実装」「UI・UX」「伸び代・将来性」の5軸です。オーディエンス投票を参考に運営が決定します。機能の優先度と発表内容はこの5軸で確認し、最新の運営案内を優先します。

### スケジュールが遅れた場合の優先順位

- 開発が遅れた場合は、P1機能や見た目の装飾から削ります。
- 「認証・非公開保存・予算制限・重複実行防止」は削りません。もし公開条件（安全対策）を満たせない場合は、無理に実APIを公開せず、サンプル画面と録画動画で発表・紹介します。
